# Averia — PRD

Аналитика успеваемости класса для школы: один XLSX-экспорт средних баллов превращается в
понятную картину класса, динамику между срезами и отчёт, который не стыдно показать
родителям и коллегам.

Документ объединяет `PRODUCT.md`, `README.md`, `DESIGN.md`, брифы поверхностей
`.impeccable/surfaces/*.md` и фактическое состояние кода. Разделы «Технологический стек»
и «Что уже сделано» описывают репозиторий на текущий момент; остальное — целевое
видение продукта.

---

## 1. Цели и задачи

### 1.1. Проблема

Классный руководитель получает выгрузку средних баллов класса — таблицу, где по строкам
ученики, по столбцам предметы, а в ячейках значения вроде `4,60`. Это сырьё: в нём нет
ни успеваемости, ни разбивки по группам, ни динамики, ни ответа на вопрос «кому нужна
помощь». Чтобы получить ответ, учитель либо сдаёт отчёт в Excel, либо просит кого-то
свести таблицу вручную. На родительском собрании или педсовете такой отчёт обычно
существует в виде одного PDF, который никто не может обновить.

### 1.2. Цель продукта

Дать учителю один инструмент, в котором **одна и та же арифметика** представлена двумя
связанными поверхностями:

- **XLSX** — рабочий прибор: живые формулы, редактируемые средние, печатный архив для
  учителя.
- **Веб-приложение** — витрина: текущая картина класса, динамика к прошлому срезу,
  история, рейтинг и категории учеников, вёрстка для проектора и телефона.

Успех измеряется так: учитель открывает файл и за минуту показывает картину класса;
после правки среднего в Excel он пересобирает отчёт одной командой; в браузере он
делает то же самое, загрузив новый файл.

### 1.3. Ключевые задачи

| # | Задача | Зачем |
|---|---|---|
| 1 | Принимать сырой XLSX-экспорт без ручной подготовки | Учитель не должен перестраивать таблицу под инструмент |
| 2 | Считать метрики по школьным правилам | Полуокругление и порог 7–8 классов — не наша воля, а регламент школы |
| 3 | Отличать «нет оценки» от нуля | `0.00` = не аттестован; иначе средние и доли молча искажаются |
| 4 | Писать рядом с числом его определение | Успеваемость и качество знаний читают как одну пару и постоянно путают |
| 5 | Показывать динамику между срезами | «Кто вырос, кто снизил» — то, ради чего делают второй срез |
| 6 | Не прятать проблемных учеников за процентами | Нужен разрез до конкретного человека и предмета |
| 7 | Быть читаемым с заднего ряда | Показ с проектора в светлом классе |
| 8 | Не протекать персональными данными наружу | Фамилии учеников — внутренние данные школы |
| 9 | Дать администратору управление без кода | Классы, учителя, приглашения |
| 10 | Построить продукт на одном языке дизайна | Один палитра оценок, один язык графиков, две равноправные темы |

### 1.4. Аудитория и сценарии

| Роль | Что делает | Где смотрит |
|---|---|---|
| Классный руководитель (предметник) | Загружает выгрузку, разбирает динамику, готовит собрание | Свой ноутбук и проектор |
| Учитель-предметник | Смотрит только свой класс, находит проблемный предмет | Телефон или планшет |
| Администрация школы | Все классы, назначения, приглашения | Рабочий компьютер |
| Родители | Читают проекцию, ничего не нажимают | Проектор в кабинете |

### 1.5. Не входит в объём

- Оценки по журналу: приложение работает с **экспортом средних баллов**, а не с
  поурочным журналом.
- Школьный документооборот, расписание, электронный дневник.
- Внешние публикации и ссылки наружу: отчёт предназначен для внутреннего показа.
- Мобильное приложение: веб, адаптированный под телефон.

## 2. Технологический стек

### 2.1. Веб-приложение (`web/`)

| Слой | Технология | Комментарий |
|---|---|---|
| Каркас | Next.js 16 (App Router) + React 19 | Server Components по умолчанию; клиентские компоненты — где нужна интерактивность |
| Язык | TypeScript 5.9, `strict` | `npm run typecheck` = `tsc --noEmit` |
| Стили | Tailwind CSS v4 (`@tailwindcss/postcss`) + CSS-переменные в `app/globals.css` | Токены объявлены как `@theme inline`, темы — через `.dark` |
| Темы | `next-themes` | Светлая и тёмная равноправны, переключатель в мастхеде |
| Компоненты | `@ui-sdk/react` + `@ui-sdk/core` (unstyled parts) | Состояния через `data-pressed`, `data-checked`, `data-selected`, `data-highlighted` |
| UI-кит поверх ui-sdk | Radix UI, `class-variance-authority`, `tailwind-merge`, `lucide-react` | 16 примитивов в `web/components/ui/` |
| Анимации | `motion` (Framer Motion) | Появление блоков, счётчики чисел |
| Уведомления | `sonner` | Тосты с действием (восстановление удаления) |
| Drawer | `vaul` | Карточка ученика |
| Графики | ручной SVG | Recharts и zod удалены как неиспользуемые — графики рисуются вручную, чтобы контролировать шрифт, палитру и отсутствие пересечений |
| Чтение XLSX | `xlsx` (SheetJS 0.20.3) | Разбор выгрузки на сервере |
| Бэкенд | Appwrite 2.7 (TablesDB + Auth), `node-appwrite` | Сессии, классы, приглашения и срезы живут на сервере |

### 2.2. Арифметика как эталон

Арифметика описана дважды и обязана совпадать:

- **Python** — `skills/class-performance-report/scripts/` (`build_grades_report.py`,
  `build_dashboard_data.py`, `build_dashboard_page.py`). Это источник истины.
- **TypeScript** — `web/lib/arith.ts`, `web/lib/parse.ts`. Порт, проверяемый на полное
  совпадение.

Ключевые правила, реализованные в обоих языках:

| Правило | Реализация |
|---|---|
| Полуокругление | `halfUp(x, grade)` → `4,50 → 5`, `4,49 → 4` |
| Порог 7–8 классов | `grade === 7 \|\| grade === 8` → округление `x − 0,1`, то есть `4,60 → 5` |
| `0.00` | Читается как «не аттестован» (`null`), а не как ноль |
| `round(x, 4)` | Порт `round4()` с half-even по двоичному значению (`toFixed(20)`) |
| Суммирование | Компенсированное суммирование Неймайера, как `sum()` в CPython 3.12+ |
| Успеваемость | Доля учеников **без двоек** (`(c5+c4+c3)/n` по классу) |
| Качество знаний | Доля учеников **без двоек и троек** (`(c5+c4)/n`) |
| По предмету | Успеваемость `(c5+c4+c3)/graded`, качество `(c5+c4)/graded` |

Категории образуют разбиение класса, сумма их численностей равна числу учеников:

1. нет оценок вовсе;
2. есть хотя бы одна `2`;
3. две и более `3` (без двоек);
4. ровно одна `3` (без двоек);
5. все пятёрки;
6. ровно одна `4`;
7. две и более `4`.

### 2.3. Дизайн-система

- Токены в `web/app/globals.css`: нейтральная шкала (графит), акцент (индиго) и
  **зафиксированная палитра оценок** — единственные тёплые цвета.
- Оценки: `5 #4c9a6a` · `4 #c9a227` · `3 #c77b3c` · `2 #dc2626` (тёмная тема —
  светлее, для контраста).
- Направление оформления — «Graphite Ledger»: измерительный прибор, волосяные линии,
  табличные цифры, акцент только для интерактивности, без вложенных карточек.
- Страница-справочник: `web/app/design-system/page.tsx` — токены, шкала, примеры
  ui-sdk-компонентов, язык графиков, обе темы.

### 2.4. Данные и приватность

- Все данные в репозитории **синтетические**: `web/fixtures/averages-sample.xlsx`
  (класс 9А, 28 учеников, 16 предметов, 445 оценок, дата 09.11.2026) и
  `web/lib/seed/payloads.json` (9А, 7Б, 10В — по два среза каждый).
- Генераторы: `web/scripts/make_fixture.py` (openpyxl, seed 20261111, включает
  пограничные значения `4.50`, `4.49`, `4.45`, `4.55`, `4.60`, `2.50`, `3.50`) и
  `web/scripts/make_seed.py` (считает эталоны Python-арифметикой).
- Реальные выгрузки исключены из git: `.gitignore` игнорирует `*.xlsx` (кроме
  `web/fixtures/`), `Анализ успеваемости*`, `averageMarks*.xlsx`.
- Персональные данные не покидают браузер: внешних ссылок и аналитики нет.

### 2.5. Проверки

```bash
cd web
npm run typecheck   # tsc --noEmit
npm run verify      # паритет TS-реализации с Python-эталоном
npm run build       # production-сборка
```

`npm run verify` читает фикстуру, прогоняет её через TS-парсер и сравнивает результат с
payload, посчитанным `build_dashboard_data.py`, поле-в-поле (`kpis`, `marks`,
`categories`, `subjects`, `ranking`, `groups`, строки учеников). Любое расхождение
останавливает скрипт с кодом 1.

Автотестов (jest/vitest/playwright) в проекте нет — покрытие обеспечивается
`verify`, `typecheck` и ручным просмотром.

## 3. Что уже сделано

### 3.1. Работа с выгрузкой

- Парсер `web/lib/parse.ts`: читает первый лист XLSX, восстанавливает битый диапазон
  `!ref`, находит строку заголовка (`Обучающийся` / `Student` / `ФИО`), определяет дату
  (`ДД.ММ.ГГГГ`), класс (`9А`, `9-Ю`) и параллель, отбрасывает пустые предметы и
  учеников без оценок, превращает `0.00` в «не аттестован».
- Страница загрузки `/upload`: drag&drop, стадии `idle → working → preview → error`,
  пошаговый прогресс («Чтение файла», «Разбор таблицы», «Расчёт показателей»,
  «Проверка целостности»), превью с ключевыми числами, предупреждения о несовпадении
  класса и о дубликате даты, подпись правила округления под параллель.
- Разбор файла выполняется на сервере (`/api/snapshots?preview=1`): браузер
  показывает числа, посчитанные той же арифметикой, что и эталон на Python.

### 3.2. Арифметика и данные

- `web/lib/arith.ts`: полный порт эталонной арифметики — KPI, распределение оценок,
  шесть категорий, группы, сильные и слабые предметы, рейтинг, строки учеников;
  инварианты проверяются функцией `assertPayload()`.
- `web/lib/dynamics.ts`: сравнение двух срезов — дельты KPI, кто вырос и кто снизил,
  новички и выбывшие, переходы между категориями, сдвиг оценок по предметам.
- `web/scripts/verify.ts`: автоматическая проверка паритета TS ↔ Python.
- Python-инструменты: сборка XLSX-отчёта с живыми формулами и статичного
  HTML-дашборда в одном файле.

### 3.3. Интерфейс приложения

- Оболочка `AppShell`: сворачиваемый сайдбар с сохранением состояния, мобильный
  top-bar с drawer, переключатель темы, меню пользователя со сбросом демо-данных.
- `/dashboard`: выбор класса, вкладки «Текущий срез / Динамика / История», полоса KPI
  с тултипами-определениями, карточки распределения и категорий, сильные и слабые
  предметы, таблицы предметов и рейтинга с сортировкой, блок «Отсутствуют оценки»,
  карточка ученика в drawer с историей по всем срезам, пустые состояния.
- `/upload`: см. 3.1.
- `/classes` (только администратор): поиск, сортировка, карточки классов, диалог
  создания/правки с валидацией имени класса (`7–11` + буква), мягкое удаление с
  восстановлением через тост.
- `/teachers` (только администратор): таблица учителей, список приглашений со
  статусами, диалог создания одноразовой magic-link ссылки на 7 дней.
- `/invite/[token]`: приём приглашения с проверкой статуса, срока и дубля email;
  обрабатываются четыре причины отказа.
- `/login`: вход по email и паролю, подсказка о том, что пароль выдаёт
  администратор, а учётная запись учителя создаётся по ссылке-приглашению.

### 3.4. Хранилище и роли

- `web/lib/store.tsx`: клиентский стейт загружается из `/api/state`; мутации идут
  через API-маршруты и возвращаются в стейт после `refresh()`.
- `web/lib/server/session.ts`: сессия Appwrite в httpOnly-cookie; пароль в браузере
  не хранится, секрет сессии остаётся на сервере.
- Роль `admin` видит все классы, `teacher` — только назначенные; проверка прав
  продублирована на сервере в каждом маршруте.
- Мягкое удаление классов и срезов с восстановлением; приглашения со статусами
  `pending / accepted / revoked`.

### 3.5. Дизайн-система и графики

- Страница `/design-system` на ui-sdk: палитра, типографическая шкала, сетка, формы,
  примеры компонентов, язык графиков, обе темы.
- Графики нарисованы вручную на SVG: горизонтальная шкала предметов, состав оценок,
  динамика среднего балла со сплайном Catmull-Rom (интерактивные тултипы при наведении
  на узлы и клавиатурная навигация), изометрическая диаграмма состава класса.
- Токены тем вынесены в CSS-переменные, включая отдельные `--iso-*` для изометрической
  диаграммы, поэтому диаграмма корректно живёт и в светлой, и в тёмной теме.

### 3.6. Инфраструктура

- `AGENTS.md` с обязательным порядком работы: скилл ui-sdk, затем
  `node_modules/@ui-sdk/react/docs/llms.txt`, а для новых компонентов —
  `core.md` по заголовку и соседний `rendering.md`.
- Установлен скилл ui-sdk (`npx skills add vercel-labs/ui --skill ui-sdk`), зафиксирован
  в `skills-lock.json`.
- `.impeccable/surfaces/*.md` — брифы поверхностей (HTML-дашборд, веб-дашборд,
  дизайн-система) с зафиксированным направлением оформления.
- `.env.local` (в gitignore) в корне репозитория: `APPWRITE_ENDPOINT`,
  `APPWRITE_PROJECT_ID`, `APPWRITE_DATABASE_ID`, `APPWRITE_API_KEY`. Читается
  Next.js через `next.config.ts` и Python-скриптами.
- Схема базы создаётся скриптом `web/scripts/provision_appwrite.ts` (`npm run provision`),
  демо-данные — `web/scripts/seed_appwrite.ts` (`npm run seed`). Оба идемпотентны.

### 3.7. Честные ограничения текущего состояния

- **Скриншотная проверка не автоматизирована.** Рендер проверяется вручную в браузере;
  автотестов и визуальных регрессий нет.
- **Отправка приглашений по почте не настроена.** В Appwrite не подключён messaging-провайдер,
  поэтому администратор создаёт ссылку и отправляет её учителю любым удобным способом —
  так же, как в прототипе.
- **Сессия проверяется перебором сессий пользователя.** У ключа Appwrite нет scope
  `account`, поэтому `getSessionUser` сопоставляет id из cookie со списком сессий
  профиля через users API. При росте числа пользователей это стоит перевести на
  отдельный scope.
- **Срезы хранятся целиком в одной строке.** Payload — это JSON примерно на 60 КБ
  на класс; он лежит в столбце `mediumtext`. Для больших школ понадобится
  разбиение на строки или хранение в Appwrite Storage.

## 4. Что дальше

Приоритеты на следующий этап:

1. **Отправка приглашений по почте.** Подключить messaging-провайдер Appwrite, чтобы
   ссылка-приглашение доходила сама.
2. **Редактирование и печать.** Экспорт дашборда в PDF/PNG для раздатки на собрании.
3. **Расширение метрик.** Предметная динамика по месяцам, планируемые результаты,
   сравнение классов параллели.
4. **Тесты.** Покрыть `arith.ts` и `parse.ts` юнит-тестами, добавить смоук-сценарий
   дашборда и API-маршрутов.
5. **Масштабирование хранения.** Разбить payload среза на строки, если школа
   насчитывает сотни учеников.
